# MRI 정본 우선 운영 스킬

## 목적

공개 사이트·오너 확정 사실·코드 변경·성장 전략을 섞지 말고, **정본 확인 → 변경 범위 확정 → Draft PR → 성장 문서 → 외부 프로필 초안** 순서로 처리한다. 사실을 추측으로 채우지 않고, 문서의 제안과 현재 운영 정본을 분리한다.

모든 사용자 보고는 첫머리에 쉬운 비유를 포함한 세 줄 요약을 둔다.

## 시작 전 입력

다음 입력을 확인한다. 모르면 `확인 불가`로 기록하고, 임의로 보완하지 않는다.

| 입력 | 기본값 또는 확인 방법 |
|---|---|
| 공개 정본 URL | `https://mriacademy.gg/`와 sitemap의 공개 페이지 |
| 코드 저장소 | GitHub의 MRI ACADEMY 사이트 저장소 |
| 오너 확정 사실 | 대회 상태·가격·실제 결제수단·신청정보 보관·배정 주체 |
| 작업 유형 | 읽기 전용 감사 / 문구 명세 / Draft PR / 성장 전략 / 외부 프로필 초안 |
| 금지 범위 | main 직푸시, 무단 배포·머지, PII 커밋, DDL·데이터 삭제, 결제 키·위젯 변경 |

사용자가 “사이트가 전부 정본”이라고 말하면 현재 공개 사이트와 오너의 최신 운영 사실을 최우선으로 둔다. 이전 Drive 문서, 채팅, 과거 가격안, 외부 프로필, 추정 일정은 이를 덮어쓰지 못한다.

## 전체 워크플로

1. **정본을 수집한다.** 홈·신청·트레이너 지원·성공 사례·이용약관·개인정보처리방침과 sitemap을 읽는다. 공개 화면의 문구, 가격, 신청 상태, 결제 안내, 데이터 고지를 표로 기록한다.
2. **충돌을 판정한다.** 각 주장에 `정본`, `제안`, `과거/폐기`, `확인 불가` 중 하나의 상태를 붙인다. 새 날짜·가격·시즌·수치·결제수단을 추측하지 않는다.
3. **오너 결정을 최소 질문으로 받는다.** 대회 상태, 실제 결제수단, 신청정보 보관 사실처럼 변경을 결정하는 사실만 물어본다. 답변용 복붙 템플릿을 제공한다.
4. **P0 문구 명세를 만든다.** 승인된 파일·정확한 교체 문구·제외 항목·금칙 표현·검증 항목을 한 문서에 고정한다.
5. **승인 후에만 코드 트랙을 연다.** 별도 브랜치에서 최소 파일만 수정하고, 검증 후 Draft PR을 연다. main 머지·배포는 별도 명시 승인 전까지 하지 않는다.
6. **성장 전략을 별도 트랙으로 정리한다.** 코드 P0와 중복 구현하지 않고, 플라이휠·KPI·수용량 게이트·오너 입력 대기 항목만 다룬다.
7. **외부 프로필은 초안만 만든다.** 공식 사이트 링크·동기화 날짜·현재 정본 가격을 넣고, 실제 게시는 오너가 수행한다.

| 사이트 내부에서 결제·보관 안내가 다름 | 오너에게 실제 운영 사실을 묻고, 수정 전에는 충돌로 유지 |

## 2. 오너 결정 템플릿

변경이 필요하면 긴 질문 대신 아래 양식을 보낸다.

```text
1. 이벤트: [종료 / 준비 중 / 신청 접수 중 / 새 문구]
2. 현재 즉시 결제 가능한 수단: [실제 가능한 수단만]
3. 신청정보 보관: [실제 전송·보관 위치와 목적]
4. 공개 가능한 통계: [중복 제거 기준이 있는 값만]
```

사용자가 조건부 승인하면, 조건을 P0 명세에 그대로 적는다. 예를 들어 신청정보 문구는 다음 네 사실을 모두 충족해야 한다.

1. 실제 서버 전송·보관 구조를 숨기지 않는다.
2. 사이트 비공개 같은 사실은 유지한다.
3. 보관 목적과 삭제 요청 경로를 한 줄씩 둔다.
4. 법적 보장·완벽 보호 같은 확언을 넣지 않는다.

## 3. P0 문구 명세

코드를 열기 전에 `P0_운영정합성_문구명세_YYYY-MM-DD.md`를 작성한다. 다음 항목을 빠짐없이 포함한다.

| 섹션 | 필수 내용 |
|---|---|
| 정본 사실 | 오너가 확정한 이벤트·결제·보관·배정 사실 |
| 변경 파일 | 각 파일과 정확한 앵커 또는 섹션 |
| 교체 문구 | 그대로 검토 가능한 최종 문안 |
| 제외 항목 | 가격 숫자, 결제 코드, DB, 정책 문서 등 이번 PR에 넣지 않는 범위 |
| 금칙어 | 제거하거나 사용하지 않을 과거 시즌·마감·자동화·과장 표현 |
| 검증 | 문자열 수, diff 범위, 문법·스모크·렌더링 검사 |

P0 문구는 사실 중심으로 작성한다. `AI 사전 진단 후 운영진 확인·배정`, `5분마다 갱신`처럼 실제 운영 흐름을 드러내되, 자동 확정이나 실시간 연동을 과장하지 않는다.

## 4. 안전한 코드·GitHub 트랙

### 승인 게이트

다음 순서를 반드시 지킨다.

1. 읽기 전용 감사와 P0 명세를 먼저 제출한다.
2. 오너가 파일 범위와 문구를 명시 승인했는지 확인한다.
3. 브랜치 생성·커밋·push·Draft PR은 외부 쓰기 작업이므로 생성 직전에 한 번 더 승인받는다.
4. 머지·배포는 Draft PR과 별개의 승인이다. 오너의 `PR #번호 머지 승인` 같은 명시 지시 전까지 실행하지 않는다.

### 구현 규칙

- `main`에 직접 push하지 않는다.
- `claude/p0-<scope>`처럼 분리 브랜치를 만든다.
- 승인된 파일만 수정한다. 예상 밖 파일이 바뀌면 중단하고 이유를 보고한다.
- PII, API 키, 토큰, 웹훅 URL, 실사용자 신청 데이터는 커밋·PR에 넣지 않는다.
- DDL·RLS·데이터 삭제는 작성만 제안하고, 오너가 Supabase SQL Editor에서 직접 실행하게 한다.
- 카드·토스·그로블 결제는 실제 공개 수단으로 확정되지 않았으면 코드·키·위젯·카피를 건드리지 않는다.

### 최소 검증

저장소에 맞는 명령을 확인해 실행한다. 기본적으로 다음을 확인한다.

```bash
git diff --check
git diff --name-only
npm ci
npm run check
node .github/scripts/check-inline-scripts.mjs
npm run smoke
```

문구 PR이면 추가로 다음을 확인한다.

- 제거 대상 문자열이 0건인지 확인한다.
- 새 시즌·날짜·결제·보관 문구가 정확히 1회 또는 의도된 횟수만 존재하는지 확인한다.
- 수정 파일이 승인된 범위와 일치하는지 확인한다.
- 정적 페이지를 브라우저로 열어 클랜·상담·신청 섹션을 확인한다.
- 로컬 환경의 YouTube·외부 API 오류는 P0 변경과 무관하면 별도 리스크로 기록하고 PR 범위에 섞지 않는다.

### Draft PR 본문

Draft PR에는 반드시 다음을 쓴다.

1. 변경한 사실과 파일별 범위
2. 명시적 제외·동결 항목
3. 명령별 검증 결과
4. 머지 전 오너 확인 체크리스트
5. `오너 승인 전에는 머지·배포하지 않는다`는 문장

## 5. 성장 전략 감리 트랙

P0 코드 트랙과 성장 전략 트랙을 분리한다. 성장 전략은 코드 구현 지시를 중복하지 않고, 배포된 코드 트랙 결과를 입력으로 수용한다.

### 전략 문서의 상태 표기

| 상태 | 의미 |
|---|---|
| 정본 | 공개 사이트 또는 오너가 확정한 현재 운영 사실 |
| 제안 | 아직 오너 결정이 필요한 명칭·상품·콘텐츠·실험안 |
| 보류 | 선행 데이터·승인이 없어 진행하지 않는 항목 |
| 폐기 | 과거 가격·일정·표현처럼 현행 정본과 충돌하는 항목 |

### 플라이휠과 KPI

기존 자산을 우선 연결한다. 새 무료 진단을 제안하기 전에 이미 있는 LV.1 필기 진단, 성장 기록, 콘텐츠, 상담 동선을 확인한다. KPI는 중복 제거 실측값만 쓴다.

| 단계 | 기본 이벤트 | 측정 원칙 |
|---|---|---|
| 문제 유입 | 콘텐츠 클릭 | 기간 내 세션·연락처 중복 제거 규칙 명시 |
| 무료 진단 | `lv1_started`, `lv1_completed` | 재시도는 첫 완료 기준 등 규칙 명시 |
| 상담 | `consult_started`, `consult_qualified` | 테스트·중복·취소 제외 기준 명시 |
| 운영 | `scheduled_capacity` | 확정 일정만 포함 |
| 성장 증거 | `case_evidence_complete` | 기준 전·후·기간·동의가 모두 있는 사례만 포함 |
| 외부 동기화 | `profile_synced` | 프로필 URL별 1건 |

### G0 수용량 게이트

강사·유입 확장 전, 오너에게 아래 7개를 입력받는다. 값이 비어 있으면 G1은 보류한다.

1. 주간 상담 가능 시간
2. 주간 강의·직강 가능 시간
3. 주간 리플레이·사후 피드백 가능 시간
4. 주간 클랜·대회·운영 고정 시간
5. 상담 1건 표준 소요 시간
6. 수업 1건 표준 소요 시간과 버퍼
7. 주간 휴식·긴급 버퍼

`총 가용시간 - 고정 운영시간 - 버퍼 = 신규 상담·수업 배정 가능 시간`으로 계산한다. 값은 추정하지 않는다.

## 6. 외부 프로필 동기화 초안

외부 프로필은 게시물이 아니라 **동기화 문안 초안**으로 만든다. 직접 게시, 결제 링크 생성, 가격 변경, 플랫폼 메시지 전송은 오너의 별도 승인 없이는 하지 않는다.

각 초안에 다음을 넣는다.

- 현재 공개 정본 가격 또는 가격 확인용 공식 링크
- 공식 사이트 URL
- 실제 동기화 날짜
- 상담·결제 안내가 사이트 정본과 다르지 않다는 문장
- 게시 전 체크리스트

다음 표현은 넣지 않는다: `첫 번째 구매자`, `무조건 승급`, `즉시 배정`, `자동 결제`, 실제 공개하지 않는 카드·토스·그로블 결제, 확정되지 않은 이벤트 신청·참가 규모, 동의 없는 후기·전적·닉네임.

## 7. 결과물과 최종 보고

작업 유형에 맞춰 다음을 제공한다.

| 작업 | 산출물 |
|---|---|
| 정본 감사 | 관측표, 충돌표, 오너 결정 양식 |
| 문구 변경 | P0 명세, 검증표, Draft PR 링크 |
| 성장 전략 | 감리 반영 v2, KPI 사전, G0 입력표 |
| 외부 프로필 | 플랫폼별 복붙 문안, 게시 전 체크리스트 |

최종 보고에는 다음을 명확히 적는다.

- 현재 정본과 관측일
- 실행한 변경과 실행하지 않은 변경
- Draft PR 번호·검증 상태·대기 중인 CI
- 머지·배포·게시 여부
- 오너가 다음으로 입력하거나 승인할 최소 항목

문서형 결과가 필요하면 Google Drive에 업로드하되, Claude 같은 외부 도구에 넘길 때는 비공개 Drive 링크만 주지 말고 파일 첨부가 필요한지 확인한다.
