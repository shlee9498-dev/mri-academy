# 무리 AI 상담봇 — 디스코드 상담 티켓 1차 답 (계약 · 2026-10-14 · 지휘 주문 · 오너 「이 순서로 돌려」)

> **이 문서는 계약만이다.** 구현은 지휘가 이 문서를 읽고 OK 한 뒤 별도 PR 로 한다.
> 소관 = MRIacademy(봇 · 상담 화면). 가격 · 환불 문구는 결제 트랙 · 토스 심사 대상이라 **있는 정본 문장만 인용**한다.

## 0. 왜 · 무엇을

- 상담이 월 10건(7 · 8월) → 4건(10월)으로 줄었다. 새벽에 들어온 문의가 아침까지 답이 없어 식는다.
- 상담 티켓 채널에 AI 가 **1차 답**을 하고 **레벨 테스트 신청 길**을 안내한다. **결정은 사람이 한다** — 가격 협상 · 일정 확정 · 환불 판단 · 배정은 하지 않는다.

## 1. 언제 답하나 — 제안: 「낮엔 30분 기다림 · 밤엔 바로」

| 시간(KST) | 동작 | 이유 |
|---|---|---|
| 09:00 ~ 24:00 | 티켓 채널 새 글 뒤 **30분** 동안 원장 · 트레이너(staff 명부) 글이 없으면 답한다 | 사람이 답할 수 있는 시간엔 사람이 먼저 · 봇이 끼어들어 대화가 갈리지 않게 |
| 00:00 ~ 09:00 | **바로** 답한다(1분 안) | 이번 주문의 목적 — 새벽 문의가 식지 않게 |

- 사람이 한 번이라도 답한 티켓은 **그 뒤로 봇이 조용하다**(사람이 이어받았다).
- 한 티켓에 봇 답은 **최대 3번**(첫 답 + 이어지는 질문 2번). 넘으면 넘김(§5)만 하고 멈춘다.
- 하루 전체 상한(예: 40번) — 넘으면 넘김만. 상한은 서버 상수(env 아님).
- **켜기 스위치**: 서버 상수 기본 꺼짐 → 오너 OK 뒤 켠다. 첫 주는 **미리보기 모드**(답을 티켓이 아니라 운영 채널에만 올려 원장이 읽어 본다) 제안.

## 2. 어디서 — 티켓 채널만

- 상담 티켓 채널 = 디스코드 **상담 티켓 카테고리 아래 채널**(지금 티켓은 다른 봇이 연다 · 이 저장소 코드에 티켓 처리 없음 — 10/14 실측).
- 봇은 **티켓 채널 안에서만** 말한다. 사람에게 **DM 을 먼저 보내지 않는다.**
- **채널 거르기(10/16 · 지휘)**: 카테고리 안에는 티켓 말고도 안내 · 트레이너 소개 · 문의 텍스트 채널과 음성 채널이 같이 있다(「강의 및 레슨」 실측). 그래서 **카테고리 id 가 맞고 + 텍스트 채널이고 + 이름이 `ticket-` 으로 시작하는 채널만** 답한다. 셋 중 하나라도 아니면 아무것도 하지 않는다(로그도 남기지 않는다). 시험(구현 PR): 같은 카테고리의 안내 채널 글 → 답 0 · 음성 채널 → 0 · `ticket-0153` → 대상.
- 필요한 설정: 카테고리 id 하나(§7 env).

## 3. 답의 근거 — 정본 문장 카드만

봇은 **카드**(정본에서 뽑은 짧은 문장 묶음 · 번호 붙음)에 있는 내용만 말한다. 카드는 서버가 정본에서 만들어 넣고, 모델은 답 끝에 쓴 카드 번호를 단다.
서버는 답에 단 카드 번호가 실제 카드인지 확인하고, **카드 밖 금액(원 · 판 숫자)이 나오면 답을 버리고 넘김**(§5)으로 바꾼다.

| 카드 | 정본(이 문장만 인용) | 비고 |
|---|---|---|
| 가격 | `config/payments.js` `PRICES` → `price-book.cjs` `chatbotPriceFacts`(레슨 10 · 21 · 33 · 99판 · 원장 강의 8번 · 세트 3종 · 레벨 테스트 20,000) | 결제 트랙 정본 · 손으로 적지 않는다(지금 `/api/chat` 과 같은 함수) |
| 레슨 길이 · 판수 | 계약 §9.11 — 1시간 5판 · 1시간 30분 8판 · 2시간 10판 · **2시간 30분 13판 · 3시간 15판**(9/30 추가분) | |
| 레벨 테스트 | `docs/leveltest-pricing-change.md` ⓞ · `price-book.cjs` 레벨 테스트 줄(60~90분 · 처음 오는 분은 모두 레벨 테스트부터 · 3시간 전 취소 전액 환불) | **옛 「상담 15,000 · 강의 상담 20,000」 문구는 쓰지 않는다** |
| 환불 | `terms.html` 제7조 표(수강 시작 전 전액 · 레슨 = 남은 판수 × 판당 단가 · 레벨 테스트 3시간 전 · 보호자 동의 철회) | **인용만** · 금액 계산 · 판단은 하지 않는다 |
| 신청 길 | 레벨 테스트 신청 페이지(`docs/intake-design.md` 신청 창구 · 사이트 신청 링크) | 「여기서 신청하면 원장이 시간을 잡아 드려요」까지만 |
| 커리큘럼 | `index.html` 원장 강의 · 반(초급 · 중급 · 심화) · VIP 룸 안내 문장 | VIP · 원장 1:1 은 금액 없이 문의 안내만(지금 챗봇 규칙 그대로) |
| 미성년 | `consent.html` · `docs/guardian-consent-design.md` 보호자 동의 안내 | §4 |

카드에 없는 질문(전적 분석 · 특정 트레이너 일정 · 「제 판수 몇 개 남았어요?」 등) → **「이건 원장님이 직접 볼게요」** 로 끝내고 넘김(§5).

## 4. 말투 · 첫 줄 · 미성년

- 첫 줄 고정: **「AI 안내예요 · 원장이 이어서 볼게요」** (ui-copy 「~요」체 · 이모지 0~1개 · 돈 · 환불 문구는 느낌표 없이).
- 미성년 신호(나이 19세 미만 숫자 · 「중학생」 「고등학생」 「초등」 「학생이에요」 「부모님」 등) → 보호자 동의 안내 카드 한 단락 + 넘김. 가격 · 신청 안내는 그다음 사람에게 맡긴다.

## 5. 하지 않는 것 · 넘김

**하지 않는 것**(모델 지시 + 서버 거르기 둘 다):
할인 약속 · 가격 협상 · 일정 확정 · 환불 판단(「환불돼요/안 돼요」) · 트레이너 배정 · 다른 수강생 정보 · **개인정보 묻기**(계좌 · 연락처 · 실명 · 주민번호). 사용자가 적어 보낸 계좌 · 전화번호는 되풀이하지 않는다.
서버 거르기: 카드 밖 금액 · 「할인」 「확정」 「환불해 드릴게요」 · 계좌 · 전화 모양 숫자 → 답 버리고 넘김 문장만.

**넘김** — 다음 중 하나면 티켓에 「원장님께 넘겼어요 · 곧 이어서 볼게요」 한 줄 + 운영진 알림:
카드 밖 질문 · 미성년 · 결제 · 환불 · 일정 · 불만 · 봇 답 3번 넘김 · 거르기에 걸림 · 모델 오류.
- 운영진 알림 = 운영 채널(§7)에 **요약 1줄**(「티켓 #채널 · 무엇을 물음 · 왜 넘김」) + 담당 트레이너가 정해진 사람이면 그 이름 멘션. 수강생에게는 DM 하지 않는다.

## 6. 기록 — 감사용(DDL 없음)

`admin_audit` 에 한 줄씩(새 표 없음):
- `action` = `consult_bot.reply` · `consult_bot.handoff` · `consult_bot.blocked`
- `target` = `discord_channel:<채널 id>`
- `detail` = `{ message_id, cards: ["price", "leveltest"], handoff: true|false, reason, mode: "preview"|"live", question_excerpt(200자 · 숫자 가림), answer }`
- 계좌 · 전화 모양 숫자는 기록 전에 가린다.
