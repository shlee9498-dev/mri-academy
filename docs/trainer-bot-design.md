# 트레이너봇 — 「한 줄 예약 + 끝났나요 벨」 설계 초안 (2026-10-14 · 지휘 주문 · 트레이너봇 세션)

**설계 · 시험 골격만 들어 있다.** 봇 코드는 경비가 계약 절을 머지한 뒤 그 절 번호대로 붙인다.
수강생은 #번호로만 적는다. 줄 번호는 이 문서를 쓴 커밋(main `9c82908`) 기준이다.

## ⓞ 요약 — 트레이너가 하는 일

| 지금 | 바뀐 뒤 |
|---|---|
| DM 으로 시간을 맞추고, 앱을 열어 칸을 열고, 예약을 넣는다(현태 칸 150개 중 13개만 참) | DM 으로 맞춘 뒤 디스코드에 **한 줄**(「금 9시 길동 2시간」) → 카드 **[저장]** |

## 2. 10/1 잠금 — 무엇이 잠겼고 어디에 붙이면 안 겹치나

- 잠긴 것(`server.js:1446~1479` · **상수 · env 아님**): `/수업등록` 레슨 전부(`LESSON_LOCK_ALL_FROM='2026-10-01'`) · `/판수정정`. 진단상담은 풀림(`CONSULT_LOCK_FROM=null`). 원장은 잠금 통과.
- 잠근 이유 = **기록을 앱 한 곳으로**(봇 기록과 앱 기록이 두 갈래로 쌓이던 것). 잠금 안내 문구 = 「수업 기록은 이제 앱에서 해줘…」.
- 새 봇은 **잠금과 충돌하지 않는다** — `/수업등록` 처럼 `lesson_sessions` 에 직접 쓰지 않고, 앱과 **같은 서버 경로**(예약 · 완료 · 노쇼)를 부른다. 기록은 여전히 한 갈래다.
- 붙일 자리:
  - 한 줄 예약 = `/수업등록` 채널(`LESSON_CHANNEL_ID` · 새 env 없음)의 일반 메시지 + 새 명령 `/수업잡기`(GmI 길드)
  - 벨 = 트레이너 DM
- ⚠️ 잠금 안내 문구는 「앱에서 해줘」 그대로라 새 봇이 생기면 **틀린 안내가 된다** → 같은 PR 에서 「한 줄로 잡고 끝나면 벨에 답해 줘」로 바꾼다(규칙이 바뀌면 안내문도 같이 · 사고 이력).

## 3. 설계

### A. 한 줄 예약

```
트레이너: 금 9시 길동 2시간            (#수업등록 채널 메시지 · 또는 /수업잡기 내용:…)
  ↓ ① 규칙 해석(lesson-line.cjs · 공짜 · 시험됨) → 못 읽으면 ② Claude → 그래도 못 읽으면 ③ 폼
  ↓ 이름 → 내 범위(scopedStudents) 안에서 찾기 · 0명/2명 이상 → 고르기 버튼(최대 5) · 범위 밖이면 「담당이 아니에요」
봇(본인에게만): 10/16(금) 21:00~23:00 · 길동님 · 2시간
              [저장] [오전 9시로] [수정] [취소]
  ↓ [저장]
서버: (그 시각에 내 열린 칸이 있으면) 그 칸에 대신 예약
      (없으면) 칸 열기 → 대신 예약 → 예약 실패면 방금 연 칸 닫기
봇: ✅ 저장했어요 · 10판 잡혔고 남은 판수 12판   ← 숫자는 서버 응답 그대로
```

- **해석 순서를 바꿨다(주문서 대비)**: 주문서는 「CLAUDE_KEY 로 해석 → 실패 시 폼」. 규칙 해석을 앞에 둔다 — 10줄 시험이 그대로 통과하는 형태(날짜 · 시각 · 길이 · 이름)는 규칙이 공짜로 같은 답을 내고, Claude 는 「담주 금욜 9시쯤」 같은 줄만 받는다. Claude 결과도 같은 검사(길이 표 · 과거 시각)를 다시 거친다.
- **표시 없는 1~11시는 오후 우선**(「금 9시」 → 21:00 · 주문서 예시와 같음) · 카드에 [오전 9시로] 버튼. 월요일 오전 칸(06:00~12:30)이 실제로 있어서 버리지 않는다.
- 요일만 쓰고 오늘 그 시각이 지났으면 다음 주 · 「다음주 금」 = 다음 달력 주 · 자정 넘는 수업은 「~다음 날 01:00」.
- 카드 · 응답은 **본인에게만**(ephemeral). 채널 원문 메시지는 저장 뒤 지우지 않고 ✅ 반응만 단다(봇이 남의 글을 지우지 않는다).
- [저장] 은 카드 하나에 한 번 — 누르는 순간 버튼을 비활성으로 바꾸고, 두 번째 누름은 「이미 저장했어요」. 서버 실패 메시지가 오면 **다시 시도 버튼을 주지 않는다**(사고 이력: 실패 재시도로 40판 중복).

### B. 끝났나요 벨

```
수업 끝(KST) + 10분 → 트레이너 DM
  🔔 10/16(금) 21:00~23:00 길동님 수업 끝났나요?
  [끝났어요] [시간 바뀜] [노쇼]
     │           │          └ 노쇼 경로(§4-③ 결정 뒤)
     │           └ 길이 고르기(1시간 … 3시간) → 완료 { games: 서버 길이표 }
     └ 완료(games 없이 = 예약 길이 그대로)
무응답 → 3시간 뒤 1번 더 → 그래도 없으면 손대지 않는다
        (예약은 booked 그대로 · 48시간 뒤 기존 「완료 확인 필요」 · 아침 9:30 채널 알림 §9.34.2 가 잡는다)
```

- 대상 = `unclosedOf` 와 같은 판정(booked · pending_review · 끝난 시각 ≤ 지금 · 머리 줄 하나 · 테스트 계정 제외) + **트레이너에게 `staff.discord_id` 가 있을 것**. 앱으로 잡은 예약도 벨이 간다(어디서 잡았든 끝나면 물어본다).
- 발송 기록 = `ops_state` `tbot:bell:<bookingId>` `{first, second, answered}` — 재기동해도 두 번 안 간다. **봇 시작 전에 이미 끝난 예약은 벨 대상에서 뺀다**(배포 첫 틱에 지난 2주치 벨이 쏟아지지 않게 · 기준 = 배포 시각).
- 버튼 멱등: 서버가 이미 멱등이다(완료 → 409 `already_recorded` · 노쇼 → 404). 봇은 그 응답을 「이미 닫힌 수업이에요」로 보여 주고 끝낸다. 누르는 즉시 버튼 비활성.
- 버튼을 누른 사람 = 그 예약 칸의 트레이너인지 다시 본다(DM 이 옮겨질 수는 없지만 원장 대신 누르기 대비).
- **자동 차감 없음** — 무응답이면 아무 상태도 바꾸지 않는다.

### C. 숫자

봇에는 판수 계산식이 없다. 길이 → 판수는 서버(`book_slot` · 완료 경로)가 정하고, 카드에는 응답 값만 쓴다.
「시간 바뀜」에서 보내는 `games` 도 `lesson-lengths.cjs` 표 한 벌에서 꺼낸다(앱이 하는 것과 같다 · §9.1).

### D. 봇이 서버 경로를 부르는 방법 — **경비 계약 절에서 정할 것**

봇과 라우트는 같은 프로세스다. 두 가지 길:

1. **라우트 몸통을 함수로 빼서 둘이 같이 부른다**(`booking-api.cjs` 가 `proxyBook({staffId, slotId, studentId, durationMin})` · `completeBooking` · `noShowBooking` 을 내보냄) — 검사 순서가 한 벌로 남는다. **추천.**
2. 봇이 자기 HTTP 라우트를 부른다 — 트레이너 인증(포털 세션 · JWT)을 봇이 만들어야 해서 비틀린다.

1번이면 `booking-api.cjs` 를 만지게 되는데 이 파일은 경비 구역이다 → 경비가 함수만 빼 주고 봇은 그걸 부른다.

## 4. 막히는 곳 — 계약 절 · 오너 결정 전에 알아야 할 것

1. **예약 마감 3시간이 대신 예약도 막는다**(`book_slot` `interval '3 hours'` · SQL 5189). DM 으로 「오늘 9시」 합의한 걸 6시 뒤에 적으면 `booking_closed`. 트레이너 일의 상당수가 당일 합의라면 **한 줄 예약이 오늘 수업에서 가장 자주 실패한다**. 풀려면 `book_slot` 에 트레이너 경로 예외(`p_skip_lead` · 대행 예약 설계 문서에 이미 있던 안)가 필요하다 → 기존 함수 변경 = **오너 OK 대상**.
2. **잔여 판수가 모자라면 예약이 안 된다**(`insufficient_games`). 「결제는 다음에」인 수강생은 한 줄 예약이 막힌다. 막히는 게 맞는지(지금 규칙 유지) 오너 확인. 봇은 「남은 판수가 모자라요(서버 기준)」 + 창구(원장)를 보여 준다.
3. **노쇼 판수**: 주문서는 「노쇼(5판)」인데, 예약 카드 노쇼(`resolve_booking 'no_show'`)는 **잡아 둔 판수 전부**(2시간이면 10판)를 쓴다. 고정 5판은 별도 경로(`POST /adjustments kind:'no_show'` · −5)이고 그 날 예약이 있으면 `booking_exists` 로 거절된다. 벨의 [노쇼]가 어느 쪽인지 = **판수 계산 결정 → 오너 OK**. 그 전까지 벨의 [노쇼]는 앱과 같은 예약 카드 노쇼로 둔다(새 규칙을 만들지 않는다).
4. **열린 칸이 없을 때 칸을 새로 여는 것**: 두 단계(열기 → 예약) 사이에 수강생 앱에 그 칸이 잠깐 보인다. 실패 시 닫지만, 한 RPC 로 묶는 게 깔끔하다 — 경비 판단(더하기만 하는 새 함수면 A).
5. **신규(prospect) · 담당 밖 수강생**은 `scopedStudents` 밖이라 못 넣는다(지금 대행 예약과 같음). 레벨 테스트 신규는 범위 밖 — 이번 범위에서 뺀다.
6. **실측 「판수 없는 시험 일정 1건」**: 개인 예약은 잔여 < 판수면 막힌다. 시험 계정(`test-accounts.cjs`)에 판수가 있어야 하거나, 레벨 테스트 칸(판수 0)으로 시험한다 → 레벨 테스트 칸으로 시험하는 쪽을 제안한다.
