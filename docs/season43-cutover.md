## 0. 즉시 보고 3건 — 처리 결과 (8/25 밤 갱신)

### (1) `BOT_REGXFER` env는 **코드에 존재하지 않는다** (사실 — 유지)

```
grep 'process.env.BOT_' server.js  →  BOT_PAYREQ 단 1건
grep 'BOT_REGXFER'      server.js  →  0건
```

**전환 승인 게이트는 이미 배포돼 있고**(PR #247 · 8/22 머지 · `queueRegistryTransfer`),
플래그가 아니라 **`registry_transfer_requests` 테이블 존재 여부**로 켜진다:

| 상태 | 동작 |
|---|---|
| 테이블 **있음** | 전환이 pending 큐로 — 오너 DM 승인/반려 버튼(자동 만료 없음, 8/25 제거) |
| 테이블 **없음**(현재) | **degrade — 종전대로 즉시 교체** + 하루 1회 오너 경고 DM |

**→ 「가동」의 실체는 env 설정이 아니라 §20 DDL 실행이다.**

### (2) §20 DDL — ✅ **실행 완료(8/25 밤 · 오너 지시 위임), 게이트 가동**

오너 지시(「② §20 DDL + clan_registry.pws_eligible + NOTIFY pgrst」)로 세션이 정본
원문(`supabase_admin_panel.sql` §20 + :273~285) 그대로 실행. 검증 원시 출력:

```
regxfer_cols = [id, discord_id, season, tier, from_platform, from_pubg_name,
  from_account_id, to_platform, to_pubg_name, to_account_id, real_name,
  active_hours, pws_eligible, status, requested_at, decided_at, decided_by, memo]
  → 18컬럼 · expires_at 없음(= #260 정본) · regxfer_rows 0 · rls_on true
regxfer_idx = [idx_regxfer_pending, registry_transfer_requests_pkey]
pws_col = 1 · registry_state = {rows: 38, pws_null: 38}(전원 미신고 — 설계 기대값)
registry_idx = [clan_registry_discord_id_season_key, clan_registry_pkey,
  idx_registry_account, idx_registry_season]
NOTIFY pgrst, 'reload schema' — 같은 배치에서 실행
```

**이 순간부터 전환은 pending 큐로 간다**(재배포 불요). 배포 로그의 `[schema] warn
(optional)` 경고는 다음 재기동부터 사라진다. 다음 = ③ `/등록계` 실기 확인(오너).

> ⚠️ **추기(8/25 밤) — 게이트 미발동 실사고 · 원인 확정 · 수정**: DDL 실행 후에도
> 오너 실기에서 게이트가 안 켜졌다. 원인은 재기동이 아니라 **코드 잔존 버그** — 쿨다운
> 조회(server.js:1574)의 select 목록에 삭제된 `expires_at`이 남아 PostgREST **42703**으로
> 조회 전체가 죽고, catch가 「테이블 미실행」으로 오판해 즉시 교체로 degrade했다(만료
> 제거 #263에서 이 줄만 누락 — 세션 과실). 실증: 같은 조회를 SQL로 재현 →
> `ERROR: 42703: column "expires_at" does not exist`(원시 출력). 수정: select에서 제거
> (전수 grep — 잔존 유일 1곳). **위 「재배포 불요」는 이 버그 탓에 이번에 한해 성립하지
> 않는다 — 수정 머지·배포(=재기동) 후 게이트가 실제로 켜진다.** ⑤ env 저장이 유발한
> 자동 재배포는 구코드 재기동이라 해소와 무관했다.

### 5-1. `GDCUP_CURRENT_SEASON`은 env가 아니라 **코드 상수**다 — ✅ 4로 변경 완료(#263)

### 5-2a. 등급 심사 규정 문구 — 정본 (관제탑 8/25 밤 확정)

### 5-4. 시즌4 BPI 산정 절차 — 9/2~9/8 창 (8/25 밤 발행 · 관제탑 검토 대기)

**실측 3건 (조사 회신)**
1. **시즌3 산정 방식** = 신청·본인확인 시점의 **실시간 API 판정**(`computeBPI` — 당시

   **사전 스냅샷 배치는 없었다** — 신청 기간이 해당 시즌 중이라 자연히 맞았던 것.

   (재기동 소실 · 개인별 저장 없음), `student_snapshots`는 수강생 축.
3. **폴백 체인 실측**(`computeBPI`: 현재 시즌 → 직전 시즌): 9/9 이후 43시즌 미플레이

   바뀐다 — 「같은 조회가 다른 값」 우려의 실증. **9/2~9/8 산정 창 필수 확증.**

**절차 (권고 — 코드 변경 0 · DDL 0)**

2. **9/8 밤 증빙 실측 1회**: `POST /api/pubg-dist/refresh?source=registry`(staff) 후

3. **9/9 이후 늦은 신청**: `verify_json.seasonSource`로 판별 — `previous`(42 폴백)면
