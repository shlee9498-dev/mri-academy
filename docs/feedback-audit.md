# 피드백 서버 실측 스크립트 — `scripts/feedback-audit.cjs`

> 2026-09-24 오너 지시 「레슨 피드백 이관 — 대상 서버 확정 · 설계 전 실측 요청」의 도구.
> **읽기 전용.** 메시지 수정·삭제·게시를 하지 않는다. `FEEDBACK_GUILD_IDS` 등 env 도 건드리지 않는다.

## 무엇을 재나

트레이너 피드백 서버(무리·현태·준구 개인 서버)마다:

1. 서버 전체 채널 수 vs 봇이 **실제로 읽을 수 있는** 채널 수 — 봇 역할 + 채널 권한 덮어쓰기를 Discord 공식 알고리즘으로 계산한다.
   서버에 들어가 있어도 비공개 학생 채널은 `View Channel` · `Read Message History` 가 따로 있어야 읽힌다.
2. 읽을 수 있는 채널마다 메시지 수(사람/봇) · 공지문 수 · 첨부 수(이미지) · 첨부 용량 · 최초·최근 메시지 날짜 · 월별 건수 — 이관 규모 추정용.
   스레드(활성 + 보관된 공개 스레드, 포럼 게시물 포함)도 채널에 합산한다.
3. 막힌 채널 목록 — 채널 이름과 **부족한 권한 이름**(디스코드 UI 표기). 오너가 봇 역할 권한을 고칠 때 그대로 찾으면 된다.
4. 채널마다 「수집기 패턴」(server.js 피드백 월이 잡는 `A/B/C그룹-이름`) 일치 여부 — 수집기가 준구 서버에서 11채널만 잡은 원인이 권한인지 채널명인지 여기서 갈린다.

## 실행

봇 토큰(`DISCORD_TOKEN`)이 있는 곳에서만 돈다. 이 저장소엔 토큰이 없고, Claude Code 클라우드 환경은 Discord API 로 나가는 길이 막혀 있다. 그래서 **오너 PC 에서 Railway 변수 주입으로** 돌린다.

```bash
git fetch origin && git checkout <이 스크립트가 들어 있는 브랜치 또는 main>
railway run node scripts/feedback-audit.cjs
```

- `railway run` 은 링크된 서비스(mri-academy)의 변수를 로컬 명령에 주입한다. 서비스가 여러 개면 `railway run --service mri-academy node scripts/feedback-audit.cjs`.
- 기본은 봇이 들어가 있는 길드 중 `GUILD_ID`(GmI 클랜) · `LESSON_GUILD_ID` 를 **뺀** 전부다. 길드 ID 를 따로 알 필요가 없다 — 보고서에 길드 **이름**이 찍히니 대상 3곳이 맞는지 이름으로 확인한다.
- 옵션: `--guilds a,b`(그것만 · 기본 제외 무시) · `--skip a,b` · `--all`(제외 없음) · `--no-history`(권한만, 몇 초) · `--max-pages N`(채널당 100건×N 상한, 기본 200) · `--out DIR` · `--json`.
- 소요: 채널당 메시지 100건에 요청 1번. 서버 3곳 합쳐 수천 건이면 1~2분. 레이트리밋은 discord.js REST 가 알아서 기다린다.

## 결과 읽는 법

- 표준출력 = 마크다운 요약. **이름만 있고 ID 는 없다** → 채팅·문서에 그대로 붙여도 된다.
- `tmp/feedback-audit/feedback-audit-<KST시각>.md` 와 `.json` 이 저장된다. `.json` 에는 채널·길드·스레드 **ID 가 들어 있으니** 올리지 않는다(`tmp/` 는 `.gitignore`).
- 요약 표의 「메시지(사람)」에서 **「공지」를 빼면** 실제 피드백 규모다. 「첨부(이미지)」와 「용량」이 Storage 로 옮길 분량.
- 「막힌 채널」 표의 「부족한 권한」을 채널 설정 → 권한 → 봇 역할에 그대로 켜면 된다. 켠 뒤 `--no-history` 로 다시 돌리면 몇 초 만에 확인된다.
- 「(실제 403 — 권한 계산과 불일치)」 는 계산상 읽힌다고 나왔는데 Discord 가 거부한 채널이다. 채널 권한 화면을 직접 확인한다.
- `⚠️ 사람 메시지 중 본문·첨부가 전부 빈 비율 …` 이 뜨면 개발자 포털의 **Message Content 인텐트**가 꺼진 것이다(REST 로도 본문·첨부가 빈 채로 온다). 수집기가 원문을 저장했던 이력이 있어 켜져 있을 가능성이 높다.
- 비공개 보관 스레드는 `Manage Threads` 가 없으면 목록에 안 잡힌다. 채널 비고에 표시된다.

## 읽기 전용 보증 (구조)

- Discord REST 의 `GET` 만 호출한다. 소스에 다른 HTTP 메서드 호출이 없고, 테스트(`scripts/feedback-audit.test.cjs`)가 소스를 검사해 CI(`npm run check`)에서 막는다.
- 게이트웨이(웹소켓) 접속이 없다 → server.js 의 봇 핸들러가 이 실행으로 돌 일이 없다. 운영 봇과 동시에 돌려도 된다.
- 메시지 본문은 세기만 한다. 저장·출력하지 않는다(공지 판별에 앞머리 「📢 피드백 채널 이용 안내」만 비교).
