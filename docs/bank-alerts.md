## §1 무엇이고 무엇이 아닌가

- **무엇** — 오너 폰(안드로이드)에 뜨는 은행 입출금 알림을 알림 전달 앱이 서버로 넘기면, 서버가 한 줄씩 쌓는다. 통장 현황을 거의 실시간으로 본다.
- **대상** — 킬내기용 통장. 지금은 사비 방지턱 통장(이름표 `sabi`), 보증금 통장이 따로 생기면 이름표를 하나 더한다.
- **참고 장부다** — 정본은 통장 거래내역이다. 폰이 꺼졌거나 앱이 멈추면 알림이 빠질 수 있고, 그래도 장부는 통장이다.
- **하지 않는 것**
  - 알림을 보고 돈 · 판수 · 신청 상태(외부 참가비 「확인」 포함)를 자동으로 바꾸지 않는다. 이번엔 받아서 쌓기만 한다.
  - `payments` · 정산 · 잠금월 · 기존 표와 칸에 손대지 않고, 외래 키 · 함수 · 방아쇠로도 잇지 않는다.
  - 결제 트랙의 토스뱅크 통장 대사와는 따로다(통장도 다르고 표도 다르다).

## §2 받는 주소 — `POST /api/bank-alerts`

### §2.1 본문

**① 줄 모양(권장 · `Content-Type: text/plain`)** — 알림 글에 따옴표 · 줄바꿈이 있어도 깨지지 않는다.

```
key=<비밀 값>
account=sabi
---
{not_title}
{notification}
```

- `---` 줄 위는 이름=값 줄(`key` · `account` · 선택 `app` · `posted` · `test`), 아래는 전부 알림 글이다.
- `{not_title}` · `{notification}` 은 MacroDroid 가 알림 제목 · 내용으로 바꿔 넣는 글자다(§7).

**② JSON(`Content-Type: application/json`)** — `{ key, account, title, text, app, posted, test }`.
알림 글에 따옴표나 줄바꿈이 들어오면 JSON 이 깨져 서버 공용 해석기가 400 으로 돌려보낸다 — 알림 전달에는 ①을 쓴다.

- **비밀 값** — 본문 `key=` 또는 머리글 `x-bank-alert-key`. 주소 뒤(`?key=`)로는 받지 않는다(주소는 로그에 남을 수 있다).
  env `BANK_ALERT_SECRET` 과 해시끼리 견준다. env 가 없거나 24자보다 짧으면 이 주소는 닫혀 있다(503).
- **시험 보내기** — `test=1` 이면 저장하지 않고 `{ ok: true, test: true }` 만 돌려준다(폰 설정 확인용).
- **크기 · 빈도** — 본문 8KB · 같은 곳에서 분당 30번까지.

### §2.2 응답

| 상태 | 본문 | 뜻 |
|---|---|---|
| 200 | `{ ok: true, saved: true, parse }` | 한 줄 저장 · `parse` = `ok` · `partial` · `unparsed`(§4) |
| 200 | `{ ok: true, saved: false, duplicate: true }` | 이미 받은 알림 — 앱이 다시 보내지 않게 200 으로 답한다(§5) |
| 200 | `{ ok: true, test: true }` | 시험 보내기 |
| 400 | `bad_body` · `bad_account` · `empty_text` | 본문 모양이 틀림 · 모르는 통장 이름표 · 알림 글이 비었음 |
| 401 | `bad_key` | 비밀 값이 틀림 |
| 413 · 429 | — · `rate_limited` | 8KB 넘음 · 분당 30번 넘음 |
| 503 | `not_configured` · `table_missing` | env 없음 · §69 실행 전 |
| 500 | `server_error` | 그 밖 |

- 로그는 `[bank-alert] saved account=sabi parse=ok dir=in` 처럼 **상태만** 남긴다 — 금액 · 잔액 · 이름 · 비밀 값은 로그에 없다.

## §3 저장 표 — `bank_alerts` (§69 · 새 표 하나 · 더하기만)

| 칸 | 뜻 | 규칙 |
|---|---|---|
| `id` | 줄 번호 | 자동 |
| `account_key` | 통장 이름표(`sabi`) | 소문자 이름표만 — 계좌 번호가 들어갈 수 없는 모양 |
| `direction` | `in` 입금 · `out` 출금 | 못 읽으면 비움 |
| `amount` | 금액(원) | 1원 ~ 10억 · 못 읽으면 비움 |
| `balance` | 잔액(원) | 알림에 있을 때만 |
| `occurred_at` | 알림 글에 적힌 시각 | 없으면 비움(받은 시각은 `received_at`) |
| `counterparty` | 입금자 이름 | **입금 줄에만** · 20자 · 공개 응답 · 로그 · 문서 · 보고에 쓰지 않는다 |
| `parse_status` | `ok` · `partial` · `unparsed` | §4 |
| `shape` | 다 못 읽은 줄의 글자 모양 | 숫자 → 9 · 낱말표 밖 한글(이름) → 가 · 로마자 → a · `ok` 줄에는 없다 · 300자 |
| `dedupe_key` | 중복 키 | sha256 hex · 유일 색인(§5) |
| `source_app` · `posted_at` | 보낸 앱 · 폰이 알림을 받은 시각 | 앱이 보내 줄 때만 |
| `received_at` | 서버가 받은 시각 | 자동 |

- **저장하지 않는 것** — 알림 글 원문 · 계좌 번호(어느 모양이든) · 출금 상대 이름 · 비밀 값.
- RLS 켬 · 정책 0(service_role 만). 다른 표와 외래 키 없음.
- 자기점검: `SCHEMA_OPTIONAL` 에 둔다(없으면 이 주소만 503 · 다른 기능은 그대로). 읽는 화면이 생기면 `REQUIRED_SCHEMA` 로 올린다.

## §4 알림 글 읽는 규칙 (`parseAlert`)

은행 알림 글 모양은 공개된 정본이 없다. 문자형(여러 줄) · 푸시형(한 줄) · 제목 + 내용 세 모양을 시험에 넣었고, 다 못 읽으면 버리지 않고 `partial` · `unparsed` 로 남긴다.

1. **시각** — `MM/DD HH:mm`(KST · 연도가 붙은 `YYYY.MM.DD HH:mm:ss` 도). 연도가 없으면 받은 해 — 받은 때보다 이틀 넘게 앞이면 지난해(12월 → 1월).
2. **잔액** — 「잔액」 바로 뒤 숫자(15자리를 넘으면 잔액으로 보지 않는다).
3. **금액** — 날짜 · 시각 · 잔액 · **계좌 모양**(별표가 낀 숫자 덩어리 · 하이픈으로 이은 숫자 묶음 · 쉼표 없는 8자리 넘는 숫자)을 먼저 지우고, 남은 숫자 중
   ① 「원」이 붙은 것 → ② 「입금」 · 「출금」과 같은 줄(또는 그 바로 아래 줄)에 있는 것 → ③ 하나뿐인 숫자.
4. **입금 · 출금** — 「입출금」(알림 이름)은 빼고 본다. 한쪽 낱말만 있으면 그쪽, 둘 다 나오면 금액 줄 · 그 앞 줄의 낱말, 낱말이 없으면 금액 앞 `+` · `−`.
   **「취소」가 있으면 방향을 정하지 않는다**(입금 취소 · 출금 취소 — 사람이 통장에서 본다).
5. **입금자 이름** — 입금일 때만. 이름만 있는 줄(문자형) 또는 「○○○님」(푸시형). 은행 · 거래 낱말이 낀 줄은 이름으로 보지 않는다.
6. **상태** — 방향과 금액을 다 읽으면 `ok`, 하나만이면 `partial`, 둘 다 못 읽으면 `unparsed`. `partial` · `unparsed` 줄에는 글자 모양(`shape`)을 남겨
   첫 실제 알림이 들어왔을 때 규칙을 맞춘다 — 오너가 알림 글을 옮겨 적을 필요가 없다.

## §5 같은 알림이 두 번 와도 한 줄

- **중복 키** = sha256(「bank-alert:v1」 + 통장 이름표 + 정리한 알림 글). 공백 · 빈 줄 차이는 같은 알림으로 본다. 표에 유일 색인.
- 두 번째부터는 저장하지 않고 200 `duplicate` 로 답한다 — 알림 전달 앱이 실패한 줄 알고 또 보내지 않게.
- 폰 쪽 다시 보내기(재시도)는 켜지 않는다(§7). 켜져 있어도 같은 알림은 한 줄뿐이다.
- **한계**
  - 같은 사람이 같은 분에 같은 금액을 두 번 보냈는데 알림에 잔액이 없으면 글이 같아 한 줄로 합쳐진다 — 정본은 통장이다.
  - 같은 거래를 문자 알림과 푸시 알림 둘 다 넘기면 글이 달라 두 줄이 된다 — 한 가지(앱 푸시)만 넘긴다.

## §6 공개 선 — 밖에 내보낼 수 있는 값

| 누가 | 볼 수 있는 것 |
|---|---|
| 공개 화면 | **숫자만** — 잔액 · 기간 입금 합계 · 출금 합계 · 건수 |
| 진행자 | 공개와 같다 |
| 오너 | 줄 목록(시각 · 금액 · 방향) + 입금자 이름 — 오너 로그인으로만(다음 주문) |

- **줄 목록은 공개하지 않는다** — 이름을 지워도 「21:15 · 10,000원」은 누가 낸 돈인지 맞출 수 있다.
- 계좌 번호 · 입금자 이름은 어느 화면 · 응답 · 로그에도 내보내지 않는다(오너 화면의 입금자 이름만 예외).
- **이번 PR 에는 읽는 길이 없다**(받아서 쌓기만). 읽는 길 · 공개 숫자는 오너가 무엇을 보일지 정한 뒤 따로 주문한다.

## §7 오너 할 일 (쉬운 말 · 이 순서대로)

**A. 서버 비밀 값 넣기 (Railway · 5분)**
1. Railway → mri-academy 프로젝트 → 서버 서비스 → **Variables** → New Variable
2. 이름 `BANK_ALERT_SECRET` · 값은 길게 아무 글자 30자 이상(비밀번호 생성기로 만들면 편해요). 메모장에만 적어 두고 다른 곳에 올리지 않아요
3. 저장하면 서버가 1~2분 다시 떠요

**B. 세션이 할 것** — 5회 뒤 지휘 「진행」을 받으면 §69 표를 만들고(스냅샷 → 실행 → 검증) 코드를 배포해요. 오너 손은 없어요.

**C. 폰 설정 (안드로이드 · 15분)**
1. **KB스타뱅킹** → 첫 화면 위 종 모양 → 환경설정 → 알림설정 → 사비 방지턱 통장의 입출금 알림 켜기.
   문자 알림도 받고 있다면 넘기는 건 앱 푸시 하나만(둘 다 넘기면 같은 거래가 두 줄이 돼요)
2. 플레이 스토어에서 **MacroDroid** 설치(무료판으로 충분해요) → 처음 열 때 「알림 접근」 허용 → 휴대폰 설정에서 MacroDroid 배터리 사용을 「제한 없음」으로
3. MacroDroid → 매크로 추가
   - **트리거**: 트리거 추가 → 검색창에 「알림」 → 「알림 받음(Notification Received)」 → 앱 고르기 = KB스타뱅킹 → 글자 조건 = 「입금」 또는 「출금」 포함
     (통장이 둘이 되면 그 통장 끝자리를 조건에 넣어 구분해요 · 끝자리는 폰에만 두고 어디에도 적지 않아요)
   - **동작**: 동작 추가 → 검색창에 「HTTP」 → 「HTTP 요청(HTTP Request)」
     - 방식 `POST` · 주소 `https://mri-academy-production.up.railway.app/api/bank-alerts`
     - 내용 형식(Content type) `text/plain` · 내용은 아래 네 줄 그대로(첫 줄의 `<비밀 값>` 자리에 A-2 값)
       ```
       key=<비밀 값>
       account=sabi
       ---
       {not_title}
       {notification}
       ```
       마지막 두 줄은 칸 옆 파란 「…」 버튼에서 「알림 제목」 · 「알림 내용」을 골라 넣어요.
       알림 글이 길어서 잘려 오면 `{notification}` 대신 「긴 알림 내용」(`{not_text_big}`)을 써요
     - 실패하면 다시 보내기(재시도) 설정은 넣지 않아요
4. **연결 시험** — 내용 맨 위에 `test=1` 줄을 잠깐 넣고 매크로 「시험 실행」 → 세션에 「시험 보냈어요」라고 알려 주면 서버 로그로 확인해요 → `test=1` 줄 지우기
5. **실제 확인** — 다른 통장에서 사비 방지턱 통장으로 1원 보내기 → 세션이 표에 한 줄 들어왔는지 · 금액 · 방향을 제대로 읽었는지 확인해서 알려 줘요

- A → B → C 순서여야 첫 알림이 버려지지 않아요(앞 단계 전에 온 알림은 서버가 받지 않고, 그 거래는 통장에만 남아요).
