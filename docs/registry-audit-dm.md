## 1. 흐름 4단계 (지시 1:1)

### 1-1. 미등록자 목록 산출 — 디스코드 멤버 ↔ `clan_registry.discord_id`

```
guild.members.fetch()  (LESSON_GUILD_ID = GmI 서버)
  → bot 계정 제외
  → clan_registry에서 discord_id 전량 조회(시즌 무관 — 한 번이라도 등록한 사람은 제외)
  → 차집합 = 미등록자
```

- **시즌 무관 대조가 맞다**: 44시즌 재등록 대상은 "42시즌 등록자"와 "완전 미등록자"가
  다르다 — 전자는 재등록 안내, 후자는 신규 등록 안내로 **DM 문안이 갈린다**(§1-3).
  산출은 두 집합을 분리해 낸다: `미등록(0회)` / `구시즌만(42) 등록`.
- 대량 fetch는 1회성 명령 안에서만(상시 캐시 금지 — 멤버 목록은 개인정보 축).

### 1-2. 등급 역할별 분류 (G · m · I) — 상위 등급 우선

- 역할 ID는 **env 3개**로 공급: `GMI_ROLE_G` · `GMI_ROLE_M` · `GMI_ROLE_I`
  (역할 이름 문자열 매칭은 개명에 깨진다 — ID 고정).
- 멤버의 보유 역할 중 최상위 하나로 분류. 어느 역할도 없으면 `기타`.
- 출력 정렬: **G → m → I → 기타** (상위 등급 미등록자 우선 대상 — 지시 그대로).

### 1-3. DM 발송 — 문안은 관제탑 발행

- **트리거는 오너 전용 명령** `/등록계검수` (옵션 `dm발송: true/false`):
  - `false`(기본) = 목록만 오너 DM으로(드라이런) — **발송 전 반드시 이 목록을 본다.**
  - `true` = 확인 버튼(오너) 후 발송.
- 문안 2종(관제탑 발행 대기): ① 완전 미등록자용(신규 등록 안내) ② 42시즌 등록자용
  (44시즌 재등록 안내 — 전환 마감 9/2·본인 명의 원칙 포함).
- **페이싱 필수**: 건당 1.2s 간격(디스코드 DM rate limit — 대량 DM은 차단 사유).
  40여 건 ≈ 1분. 진행/실패를 오너에게 요약 회신.
- **DM 차단 계정은 실패 목록으로 회신**(강제 불가) — 채널 멘션 공지로 보완(운영 판단).
- 발송 이력: `ops_state`에 `regaudit:<날짜>` 키로 기록(재실행 시 중복 발송 방지 —
  같은 날 재실행이면 미발송분만).

### 1-4. `/등록계현황`에 「미등록 N명」 섹션

- 기존 현황(오너 DM 전용)에 **수치 요약** 추가: `미등록 N명 (G a · m b · I c · 기타 d)`.
- **이름 목록은 현황 본문에 넣지 않는다** — 길이 폭발(디스코드 2,000자)과 노출 최소화.
  목록이 필요하면 `/등록계검수`(드라이런)로 뽑는다.
- 멤버 fetch 실패(권한·장애) 시 섹션 생략 — 현황의 다른 섹션을 죽이지 않는다(기존
  degrade 관례).
