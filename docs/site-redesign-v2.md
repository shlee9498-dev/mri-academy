## 3. 카드 스펙

### 3-1. 축약 카드 (히어로 바로 아래 · 3열 그리드, 모바일 1열)

각 카드 = 기존 프로필 이미지(인라인 base64 `<img>` 태그 이동) · 이름/직함 · **한 줄 철학**
(§4 발췌 그대로) · **담당 n/25** · 대표 후기 1줄 · CTA 2개 `[상담 신청]` `[가격·결제 보기]`.

- **담당 n/25**: 「정원 25」 문구는 `:764` 실재. **동적 n의 기존 카운터는 index에 없다**
  — 서버 카운트 API 필요. **스펙은 §3-1a로 발행(관제탑 8/22 지시) — 구현 미착수 유지.**
- **대표 후기 1줄**: 원문 소스 미지정 — 관제탑/오너가 트레이너별 1줄 지정 필요(지어내지 않음).

### 3-1a. 공개 카운트 API 스펙 (발행만 · 구현 미착수 — 관제탑 8/22)

- **`GET /api/trainer-capacity`** — 공개(무인증). 응답에 **이름·금액·학생 식별자 0건**, 수치만.
  ```json
  { "cap": 25,
    "trainers": [ { "name": "현태", "active": 21 }, { "name": "준구", "active": 18 } ],
    "asOf": "2026-09-04T03:00:00Z" }
  ```
- **집계 정본 = `v_panel_roster`**: 트레이너별 활성 행 count. 패널 로스터와 같은 뷰를 세는
  것이라 패널 숫자와 사이트 숫자가 어긋날 수 없다(별도 산식 금지).
- **`cap`은 서버 상수가 정본**(현행 25) — 프론트는 응답의 `cap`으로 렌더, 본문 하드코딩
  금지(gdcup-meta의 「표를 복제하지 말 것」과 같은 원칙. 「정원 25」 정적 문구 `:764`는
  카운터 구현 시 API 값 렌더로 교체).
- **캐시**: 서버 인메모리 60s TTL — 공개 페이지 트래픽이 Supabase 호출로 직결되지 않게 상한.
- **degrade**: 조회 실패 시 마지막 캐시값 서빙(`asOf`로 시점 노출), 캐시도 없으면
  `{"cap":25,"trainers":[]}` → 프론트는 카운터·자동 전환을 **표시하지 않고** 기존 정적
  문구로 폴백(공개 화면에 에러·빈 숫자 노출 금지).
- **§6 게이트 연동**: 프론트가 `active ≥ cap−1`(24/25)에서 결제 카드 → 「상담으로 대기
  신청」 전환. 판단 로직은 프론트, 수치는 이 API 단일 소스.

### 3-2. 확장 상세 — 역할별 결제 카드 (오너 ⓐ: Groble 링크 공개가 공식 경로)

| 트레이너 | 상담 | 결제 카드 |
|---|---|---|
| 무리 | 강의상담 `YYKAzR` | 직강 초/중/심 · VIP·세트 |
| 현태 | 레슨상담 `ee9ivS` | `6HdzWn`(10판) · `Pyf4qp`(21판) · `9a5iRh`(33판) |
| 준구 | 레슨상담 `ee9ivS` | `F6HzYD`(10판) · `QqZBnF`(21판) · `EJYsVv`(33판) |

Groble 링크 형식·직강/VIP·세트 코드의 정본은 결제 트랙 정가표 상수와 함께 확정(§6).

### 3-3. 실제 코칭 영상 섹션 (신설 — 관제탑 8/22 지시 · 설계만 발행)

위치: 트레이너 카드 블록 바로 아래(§2 순서 3). 반별 피드백 영상 3편, 초급→중급→심화.

| 반 | YouTube id | 한 줄 설명(관제탑 원문) | 앵커 id |
|---|---|---|---|
| 초급 | `HYQ0TSxfHqs` | 기본기부터 다시 잡는 과정 | `#cv-basic` |
| 중급 | `2MhqPAsc2EU` | 판단 순서를 만드는 과정 | `#cv-mid` |
| 심화 | `L0m6bVuI6As` | 상황별 기준을 세우는 과정 | `#cv-adv` |

**게시 게이트 — 목록 데이터 기반(3개 하드코딩 금지, 지시 그대로)**

```js
// index.html 인라인 스크립트 상수 — 섹션·앵커 링크가 전부 이 목록 하나에서 렌더된다.
const COACHING_VIDEOS = [
  // published: 게이트 3항목(①개인정보 ②당사자 동의 ③패치 의존) 오너 확인 후에만 true.
  { level: "초급", anchor: "cv-basic", yt: "HYQ0TSxfHqs", copy: "기본기부터 다시 잡는 과정", published: false },
  { level: "중급", anchor: "cv-mid",   yt: "2MhqPAsc2EU", copy: "판단 순서를 만드는 과정",   published: false },
  { level: "심화", anchor: "cv-adv",   yt: "L0m6bVuI6As", copy: "상황별 기준을 세우는 과정", published: false },
];
```

- 렌더는 `published === true`인 항목만. **기본값 false** — 게이트 통과 전 게시 금지가
  코드 기본값으로 보장되고, 반별 독립 판정 → 통과분만 게시가 목록 필터로 성립한다.
- 통과 **0건이면 섹션 루트 자체를 렌더하지 않는다**(빈 헤더 금지). 일부 통과 시 그리드는
  개수대로 자연 축소(빈 자리 placeholder 금지).
- **무리 확장 상세(§3-2)의 직강 초/중/심 → 영상 앵커 링크도 같은 상수를 읽는다** — 1:1
  대응(초급↔`#cv-basic` 등)이므로 미게시 반은 **링크 자체를 미노출**(죽은 앵커 금지).
- `published` 전환은 게이트 확인표(아래) 확인 후 커밋으로 기록 — 판정 이력이 git에 남는다.

**lite-embed 구현 스펙** (iframe 3개 즉시 로드 금지 — LCP 사유는 지시 그대로)

- 초기 렌더 = **정적 썸네일만**: `https://i.ytimg.com/vi/{yt}/hqdefault.jpg`(480×360).
  `loading="lazy" decoding="async"` + `aspect-ratio: 16/9` 고정 박스(CLS 0).
  maxresdefault는 영상에 따라 404/회색 프레임이 나와 쓰지 않는다.
- 마크업은 `<button>`(키보드 접근) + `aria-label="{level} 피드백 영상 재생 — {copy}"`.
  ▶ 표시는 반투명 다크 오버레이 — **골드 글로우 금지**(3곳 원칙 유지), 골드는 반 라벨
  텍스트 포인트 이하로만.
- 클릭 시 해당 카드에만 iframe 주입:
  `https://www.youtube-nocookie.com/embed/{yt}?autoplay=1&rel=0`
  + `title="{level} 피드백 영상"` `allow="encrypted-media; picture-in-picture"` `allowfullscreen`.
  - **youtube-nocookie**(privacy-enhanced) 도메인 사용.
  - **로드 시 자동재생·자동음성 0은 구조로 보장** — 페이지 로드 시 iframe이 0개다.
  - ⚠️ 주입 iframe의 `autoplay=1`은 「클릭 제스처에 의한 재생」의 표준 구현(빼면 썸네일
    클릭 후 유튜브 재생 버튼을 또 눌러야 하는 이중 클릭). 자동재생 금지를 엄격 해석해
    이것까지 뺄지는 **관제탑 판정 1건** — 빼는 쪽도 파라미터 한 개 제거로 끝난다.
  - `rel=0` — 종료 화면의 관련 영상을 같은 채널로 제한.
- 새 컴포넌트 스타일 신설 금지(지시 그대로): §3-1 카드와 **같은 그리드 규칙**(데스크톱
  3열 / 모바일 1열 세로 스택)과 `--surface-1`·기존 radius/border 토큰을 상속. 신규 CSS는
  aspect-ratio 박스 + 재생 오버레이 최소 범위로 한정.
- 섹션 카피(안 — draft): 제목 「실제 코칭 영상」 · 부제 「반별 피드백 — 초급 · 중급 · 심화」.

**게시 전 게이트 확인표 (오너 — 반별 독립 판정 · 확인 전 게시 금지)**

| 반 | ① 개인정보 노출 없음 | ② 당사자 공개 동의 | ③ 패치 의존 내용 확인 | → published |

## 5. 성장 사례 6건 태깅 가능 여부 — 회신

`#cases`(`:542~:553`) 6건(세\*\*·차\*\*·숑\*\*·제\*\*·지\*\*·텐\*\*)의 **마크업에 트레이너 정보가
없다**(grep 0건). → 태깅은 렌더 문제가 아니라 **데이터 문제**: 6건의 담당을 관제탑/오너가
지정해 주면 카드당 태그 1개 추가로 구현 가능(구조 변경 불요). **담당 지정 요청.**
