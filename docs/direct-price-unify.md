# 원장 직강 가격 하나로 · 세트 폐지 — 가격 계약 (2026-10-19)

> 오너 결정 10/19 원문: 「초,중,심화 가격 다 합쳐야할듯 이무리 직강반은 29만원으로 8회(24시간)」 · 세트 「세트 없애기」 · 적용 「새 신청분부터 바로」.
> 가격은 토스 심사 대상이다(CLAUDE.md). **사이트 문구는 오너 확인 화면을 먼저 보인 뒤** 바꾼다(§5).
> 이 문서가 가격 쪽 정본이다 — 사이트 · 앱 · 디자인은 절 번호로 받아 간다.

## §1 새 가격 (10/19 새 신청분부터)

| 상품 | 금액 | 구성 |
|---|---|---|
| **원장 직강 8회** | **290,000원** | 1회 3시간 × 8회 = 총 24시간 · 단계 구분 없이 한 가격 |
| 레슨 10판 | 45,000원 | 그대로 |
| 레슨 21판 | 90,000원 | 그대로 |
| 레슨 33판 | 140,000원 | 그대로 |
| 레슨 99판 | 420,000원 | 그대로(33판 × 3) |
| 레벨 테스트 | 20,000원 | 그대로 |

- **폐지**: 직강 단계 가격(초급 250,000 · 중급 270,000 · 심화 290,000) · 세트 3종(초급 280,000 · 중급 340,000 · 심화 405,000).
- 직강과 레슨을 같이 하려면 **따로 산다**(직강 290,000 + 원하는 레슨 판수). 묶음 할인은 없다.
- 반(초급 · 중급 · 심화 기수)은 수업 내용 구분으로 남는다 — **가격은 같은 290,000**. 초급 기수는 레벨 테스트 직후 바로 들어갈 수 있다(오너 10/18).

## §2 이미 결제한 사람 — 그대로 (소급 없음)

- 옛 단계 가격(250,000 · 270,000) · 옛 12회 상품 · 세트로 이미 결제한 사람은 **결제 · 회차 · 판수 그대로**다. 차액 청구 · 환불 없음.
- 기존 `payments` · `courses` · `lesson_enrollments` 행은 고치지 않는다. 옛 세트 결제(`kind='set'` 2행 · `deposit_ref` 묶음)도 그대로 읽힌다.
- 환불 계산(남은 회차 × 회당 단가)은 **그 사람이 실제로 낸 금액 ÷ 결제 회차**를 쓴다 — 새 가격으로 다시 계산하지 않는다.

## §3 정가표 (`config/payments.js`) — 이 PR

- 키 정리: `direct8_beginner` · `direct8_inter` · `direct8_advanced` · `setEntry` · `setLeap` · `setMaster` 를 지우고 **`direct8` = 290,000** 하나를 둔다.
  표시 이름 `PRODUCT_LABELS.direct8` = 「원장 직강 8회」.
- `SET_COMPONENTS` · `setListPrice()` 도 지운다(세트가 없다). 읽는 곳 0곳(실측: 저장소 전체에서 config · 시험 · `price-book.cjs` 뿐).
- 그로블 링크 키도 같이 정리한다(`GROBLE_LINKS.direct8` · 빈 값).

## §4 상담 챗봇 정본 카드 (`price-book.cjs`) — 이 PR

- 「원장 강의 초급 / 중급 / 심화」 줄 → 「원장 직강 8회(1회 3시간 · 총 24시간) 290,000원 · 반 단계와 상관없이 같은 가격」.
- 「세트」 줄 → 「세트 상품은 없습니다. 직강과 레슨은 따로 신청합니다」.
- 금액은 지금처럼 전부 `PRICES` 에서 읽는다(손으로 적지 않는다).

## §5 사이트 · 앱 · 디자인이 고칠 곳 (지휘가 넘긴다 · 이 PR 밖)

| 받는 곳 | 고칠 것 |
|---|---|
| 사이트(지휘 → 사이트 세션) | 가격 표 · 약관 가격 줄 · 문구 표 — 직강 3단계 칸 → 290,000 한 칸 · 세트 칸 지우기. **오너 확인 화면 먼저** |
| 반장(앱) | 앱 가격 표기 — 직강 단계 가격 · 세트 표기 지우기. 앱 결제 상품 목록(`/pay-info`)은 원래 판수 4종만이라 바뀌는 것 없음 |
| 디자인 | 사용설명서 · 공지 카드의 가격 줄 |

## §6 봇 · 정산 영향

- `/결제신청`(트레이너 봇 · `server.js`) — 「세트」 고르기를 지운다. 이미 등록된 디스코드 명령에 남아 있어 누르면 「10/19부터 세트는 팔지 않아요」로 막는다(이 PR).
  새 직강 결제는 지금처럼 「강의」로 올린다(§18d 가 강의는 수동 편입).
- **정산 영향 없음** — 정산 엔진(`admin-panel.js`)과 §18d `payreq_apply` 는 단계 가격 · 세트 정가를 **계산 전제로 쓰지 않는다**.
  직강 정산은 강의 행의 `courses.unit_price`(결제액 ÷ 회차)를 쓰고, 새 직강은 290,000 ÷ 8 = **36,250**이 된다(종전 심화와 같은 값).
  §18d 의 세트 분해 표(280,000 · 340,000 · 405,000)는 DB 함수 안에 그대로 남는다 — 새 세트 결제가 안 들어오므로 쓰이지 않을 뿐이고,
  지우면 기존 함수 교체(B 구간)라 건드리지 않는다.
