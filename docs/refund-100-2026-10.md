# 수강생 #100 중도 환불 — 장부 기록 준비 (2026-10-07)

> 상태: **실행 전 초안.** 이체는 오너가 직접 한다. 아래 SQL 은 **「오너가 이체했다」는 말과 통장 출금 줄이
> 확인된 뒤**에만 실행한다(통장이 정본). 그 전에는 운영 DB 에 쓰지 않는다.
> 이 문서에는 이름 · 계좌 · 연락처를 쓰지 않는다 — 수강생은 `#100`(students.id)으로만 적는다.

오너 확정(10/7): 「3회 · 305,625원」 「낸 돈 비례」. 상담비 15,000 은 환불하지 않는다.

## 1. 재계산 (10/7 읽기 조회)

| 항목 | 실측 | 계산 |
|---|---|---|
| 원결제 | `payments` #200 강의분 265,000(세트 · `course_id` 18) · #201 레슨분 140,000(세트 · 33판 · 등록 144) · #202 상담 15,000 — 셋 다 9/16 계좌이체, #200 · #201 은 `deposit_ref` `D20260916-01` 한 줄 | — |

| 등록 144 | `games_total` 33 · `bonus_games` 0 · `paid_amount` 140,000 · `lesson_sessions` 0건 | 엔진 환불식 `round100(paid_amount × 유상잔여 ÷ 유상판수)` = 140,000 × 33 ÷ 33 = **140,000** |
| 합계 | | **305,625** (위약금 없음) |

### 1.1 ⚠️ 실행 전 확인 — 10/6 참여형 예약이 「예약됨」으로 남아 있다

`slot_bookings` #61 — #100 · 레슨 담당 트레이너(staff 5) · **10/6(월) 22:00 참여형 2시간** · `status='booked'`
(같은 칸의 다른 예약도 `booked` · 그날 그 트레이너의 `lesson_sessions` 0건 = 아직 정리 전).

| 결과 | 레슨 환불 | 합계 |
|---|---|---|
| 안 왔다 · 수업 없음 | 140,000 | **305,625** |
| 왔다 — 트레이너가 수업 기록을 먼저 적는다(최근 참여형 기록 4~8판) | 엔진 환불식으로 다시 계산 — 4판 123,000 ~ 8판 106,100 | 288,625 ~ 271,725 |

참여형 예약은 선차감이 0판(`games_held` 0)이라 「안 왔다(no_show)」로 닫아도 지금 규칙에서는 판수가 줄지 않는다
(노쇼 5판 · 차감분을 사용으로 보는 규칙 7 은 아직 미시행 — `booking-policy-design.md` §0).
**예약은 트레이너가 평소 화면에서 닫는다**(왔으면 수업 기록 · 안 왔으면 노쇼/취소). 아래 SQL 은 예약을 직접
고치지 않고, ⓪에서 「더 이상 `booked` 가 아님」만 확인한다.

## 2. 장부에 넣는 방법

### 2.1 환불 = 음수 `payments` **2행** + 같은 `deposit_ref`

통장 출금 1줄(305,625)을 **행 2개**로 넣고 `deposit_ref` 하나로 묶는다. 음수 1행으로는 못 넣는다.

- `chk_payments_single_attribution` — 한 행의 귀속처는 `course_id` · `lesson_enrollment_id` 중 최대 하나다.
  이 환불은 강의 18 과 등록 144 양쪽에 붙어야 한다.
- 「통장 1줄 = `deposit_ref` 1개」(`lecture-data-model.md` §9.4 · §9.5, 2026-08-16 개정) — 세트 결제를 2행으로
  나눈 것과 같은 규칙을 환불에도 쓴다. 원결제 #200 · #201 도 `D20260916-01` 한 줄이었다.
- 단일 귀속 환불은 1행 · `deposit_ref` null 이었다(`lesson-enrollment-model.md` §3.1). **두 귀속처에 걸친 환불은
  이번이 처음**이다.

| | 강의행 | 레슨행 |
|---|---|---|
| `amount` | −165,625 | −140,000 |
| 귀속 | `course_id` 18 | `lesson_enrollment_id` 144 |
| `kind` | `refund` | `refund` |
| `games` · `payout_rate` | 0 · 0 | 0 · 0 |
| `paid_at` | 실제 이체일(10월) | 같음 |
| `settled_period` | 비움 → `paid_at` 월(10월 · 잠금 밖) | 같음 |
| `pay_channel` · `fee_amount` | `transfer` · 0 | 같음 |
| `deposit_ref` | `D<이체일 YYYYMMDD>-<그날 순번 2자리>` (10월에는 아직 없음 → `-01`) | 같은 값 |
| `memo` | 원결제 #200 · 3회 진행 · 미사용 5회 × 33,125 · 오너 확정 10/7 | 원결제 #201 · 33판 미사용 전액 · 오너 확정 10/7 |

**`kind` 는 `refund`** — `lesson-enrollment-model.md` §3.1 의 「원결제의 kind」 문장은 그 뒤 관례와 다르다.
8/17 이후 환불 행(#172 · #175 · #225)은 전부 `refund` 이고, 코드가 이 값을 본다:
트레이너 포털 강의 「환불일」(`trainer-portal.cjs` `refundedOn`) · 공개 통계에서 환불한 수강생 빼기
(`public-metrics.cjs`). 원결제 kind(`set`)로 넣으면 트레이너 포털이 음수 행을 「낸 날」로 보여 준다.
(§3.1 문장 정리는 별건 — 이 기록과 같이 하지 않는다.)

**손대지 않는 것** — 9/16 원결제 3행(#200 · #201 · #202 · 9월 잠금) · 출석 3건(오너가 3회로 확정) ·
상담 #202(환불 없음). 9월 행은 `payments` 잠금 트리거(`fn_payments_lock_guard`)가 막는다 — 고칠 일도 없다.

### 2.2 강의 18 · 등록 144 닫기

| 대상 | 바꾸는 것 | 그대로 두는 것 | 근거 |
|---|---|---|---|
| `courses` 18 | `status` `active` → **`cancelled`** · `ended_on` = 10/4(마지막 출석) · `memo` 한 줄 | `units_total` 8 · `unit_price` · 출석 3건 | `courses` 상태값에 `refunded` 가 없다. 전액 환불한 강의 2 (#225)가 `cancelled` 다. 계약은 계약이라 회차를 줄이지 않는다(§9.4) |
| `lesson_enrollments` 144 | `status` `active` → **`refunded`** · `ended_on` = 이체일 · `memo` 한 줄 | `games_total` 33 · `paid_amount` 140,000 | `lesson-enrollment-model.md` §3 「전액 환불이면 `status='refunded'`」 |

- 앱 잔여 판수는 `active · done · paused` 등록만 센다(`student-portal.cjs`) → `refunded` 로 바꾸면 33판이 잔여에서 빠진다.
- `courses.confirmed_units`(오너 확인 회차 · 지금 0)는 오너 확인 칸이라 이 기록에서 건드리지 않는다.
- `students` #100 의 `status`(지금 `active`)를 `done` 으로 바꿀지는 오너가 정한다 — 아래 SQL 에 넣지 않았다.

### ⓪ 실행 전 — 전제 확인 + 지문 (읽기만)

### ① 실행 — 한 트랜잭션

```sql

-- 1-1. 환불 2행 (같은 deposit_ref 가 이미 있으면 0행 — 재실행 안전)

  (student_id, paid_at, amount, games, kind, payout_rate, pay_channel, fee_amount, deposit_ref,
   course_id, lesson_enrollment_id, memo, source)
select * from (values
  (100::bigint, '<이체일>'::date, -165625, 0, 'refund', 0.00, 'transfer', 0, '<deposit_ref>',
   18::bigint, null::bigint,
   '중도 환불 강의분 — 심화 8회 중 3회 진행(9/29 · 10/2 · 10/4) · 미사용 5회 × 33,125(낸 돈 265,000 ÷ 8) · 위약금 없음 · 원결제 #200 · 오너 확정 10/7',
   'manual'),
  (100::bigint, '<이체일>'::date, -140000, 0, 'refund', 0.00, 'transfer', 0, '<deposit_ref>',
   null::bigint, 144::bigint,
   '중도 환불 레슨분 — 33판 미사용 전액(140,000 × 33 ÷ 33) · 원결제 #201 · 오너 확정 10/7',
   'manual')
) as v(student_id, paid_at, amount, games, kind, payout_rate, pay_channel, fee_amount, deposit_ref,
       course_id, lesson_enrollment_id, memo, source)
where not exists (select 1 from public.payments p where p.deposit_ref = v.deposit_ref);
-- 기대: INSERT 0 2

-- 1-2. 강의 18 닫기
update public.courses
   set status = 'cancelled', ended_on = date '2026-10-04', updated_at = now(),
       memo = concat_ws(' · ', memo, '10/7 중도 환불 — 3회 진행 · 미사용 5회 165,625 환불(<deposit_ref>)')

-- 1-3. 등록 144 닫기 (진행 기록이 생겼으면 0행 → 멈추고 다시 계산)

   and not exists (select 1 from public.lesson_sessions where lesson_enrollment_id = 144);
```

### ② 검증 (읽기만)

```sql
select
  (select count(*) from public.payments where deposit_ref = '<deposit_ref>')                        as refund_rows,      -- 기대 2
  (select sum(amount) from public.payments where deposit_ref = '<deposit_ref>')                     as refund_sum,       -- 기대 -305625

  (select string_agg(coalesce(course_id::text, '-') || '/' || coalesce(lesson_enrollment_id::text, '-'), ',' order by id)
     from public.payments where deposit_ref = '<deposit_ref>')                                      as attribution,      -- 기대 18/-,-/144
  (select status || ' ' || ended_on from public.courses where id = 18)                              as course_18,        -- 기대 cancelled 2026-10-04

  (select count(*) from public.payments_history ph
     where ph.op = 'INSERT'
       and ph.payment_id in (select id from public.payments where deposit_ref = '<deposit_ref>'))   as history_rows;     -- 기대 2 (INSERT 이력)
-- 그리고 ⓪ 0-2 를 다시 돌려 pay_200_202 · attendance_18 지문이 ⓪과 같은지 본다.
```

## 5. 실행 순서

1. 레슨 담당 트레이너가 10/6 참여형 예약(#61)을 닫는다 — 왔으면 수업 기록부터(§1.1).
2. 오너가 이체한다 → 「이체했다」 + 통장 출금 줄(날짜 · 금액) 확인.
3. 세션이 ⓪ → ① → ② 순서로 실행하고, 결과(행 수 · 합 · 지문)를 보고한다.
4. 이 문서의 `<이체일>` · `<deposit_ref>` 를 실제 값으로 채워 Draft 를 머지한다.
