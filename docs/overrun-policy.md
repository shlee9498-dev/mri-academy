# 초과 진행 처리 정책 (미수 vs 아카데미 부담)

> 관제탑 2026-08-19 확정. **1~3(봇·패널 구현)은 봇 v2 재배선(8/24~27) 작업이다 — 지금 착수하지 않는다.**
> 이 문서는 정책 기록 + 실측 검증이다.

---

## 1. 원칙

초과 진행 시 **미수**와 **아카데미 부담**을 데이터상 구분한다. 음수로 뭉치면 미수 목록이
오염되고 봇 경고·예약 차단이 오작동한다.

| 구분 | 데이터 표현 | 청구 |
|---|---|---|
| **미수** | 잔여 음수 유지 | 청구 대상 |
| **부담** | 무상 등록 행 추가 → 잔여 0 | 청구 안 함 |

**분기 기준**
- 사전 고지 없이 발생 **+ 10판(45,000) 이하** → 부담
- 사전 고지 있음 **또는** 고액 → 미수 청구
- **트레이너 지급은 어느 경우든 진행 판수 전액**(진행 기준 정산)

---

## 2. ⚠️ `bonus_games` 상계안은 폐기됐다 — 실측으로 확인했다

관제탑 초판 지시는 「부담 = `bonus_games` 상계」였고, 확정판이 이를 뒤집었다.
**확정판이 옳다.** 코드와 실데이터로 검증했다.

`admin-panel.js:193` `refundAmount()`:

```js
const bonus = Math.min(total, Math.max(0, Number(enr.bonus_games || 0)));
const paidGames = total - bonus;                       // ← 유상 판수
return round100((Number(enr.paid_amount) * paidRemain) / paidGames);
```

**`bonus_games`는 `games_total`에 포함된 내수다.** 환불 분모가 `games_total − bonus_games`이므로
**기존 등록 행의 `bonus_games`를 올리면 유상 판수가 줄고 판당단가가 부푼다.**

김예지(59) 등록 101 실측(`games_total=21 · bonus_games=0 · paid_amount=80,000`):

| | 유상 판수 | 판당단가 |
|---|---:|---:|
| 현행 | 21 | **3,809.52** |
| `bonus_games`를 7로 올리면 | 14 | **5,714.29** |

**+50% 왜곡.** 그리고 `chk_le_bonus_range`는 이 값을 통과시키므로
**환불이 실제로 일어나는 시점까지 아무도 모른다.**

## 3. 정본 방식 — 부담분은 **별도 등록 행**으로 추가한다

```
games_total = 부담 판수
bonus_games = 동일 값        ← 유상 판수 0
paid_amount = 0
memo        = 부담 사유 · 판정일
```

**왜 이게 맞는가** — 유상 판수와 판당단가가 **원래 행에 그대로 보존**되고 잔여만 0이 된다.
부수 효과로 미수/부담 구분이 데이터에 남는다: 부담분은 `paid_amount = 0`인 행이므로
**미수 목록은 `paid_amount > 0`만 조회하면 된다**(별도 플래그 컬럼 불요).

`refundAmount()`가 이 행을 만나면 `paidGames = 7 − 7 = 0` → `if (!(paidGames > 0)) return null`
(「전액 무상 등록 — 환불 대상 없음」)으로 정확히 떨어진다. **코드가 이미 이 형태를 상정하고 있다.**

## 4. 김예지(59) — 오너 실행 완료 (2026-08-19 19:45Z 실측)

| 대상 | 값 |
|---|---|
| 세션 130 | 10판 · 8/19 · `created_by='owner_sql'` |
| 등록 **124** | `games_total=7 · bonus_games=7 · paid_amount=0 · started_on=8/19` |
| memo | `초과 진행 아카데미 부담 7판 (2026-08-19 오너 판정) — 무상, 환불 대상 아님, 미수 아님` |

**검증 결과** — 정본 방식대로 들어갔다.

| 항목 | 값 |
|---|---:|
| 부여 총 | 21 + 7 = **28** |
| 진행 총 | **28** (8 + 40 − 30 + 10) |
| 잔여 | **0** ✅ |
| 유상 판수 | (21−0) + (7−7) = **21** — 보존됨 ✅ |
| 판당단가 | **3,809.52** — 왜곡 없음 ✅ |

정산 시 **준구 지급은 10판 전액 기준**이다(3판으로 깎지 않는다).

### 4-1. 부수 발견 — `created_by` 표기가 두 갈래다

`lesson_sessions.created_by`에 **`owner-sql`(하이픈)** 과 **`owner_sql`(언더바)** 가 공존한다.
현재 백필·집계는 `created_by = 'seed'`만 구분하므로 **영향 없다.**
다만 앞으로 `owner_sql`로 필터하는 코드가 생기면 하이픈 행이 조용히 빠진다 —
표기를 하나로 고정하거나, 필터를 쓸 때 `ilike 'owner%'`로 받는다.

### 4-2. ⚠️ 부담 행은 그 학생을 세션 귀속 백필의 B구간에서 빼낸다

부담 행이 생기면 active 등록이 2건이 되어 **「유일 등록」 조건이 깨진다.**
김예지의 미귀속 6행이 그대로 D구간(FIFO 필요)으로 내려갔고, 백필 대상이
**29 → 23행**으로 줄었다(`docs/session-enrollment-backfill.md` §2-0).

→ **부담 행 추가보다 세션 귀속 백필을 먼저 실행하는 쪽이 항상 싸다.**

## 5. 구현 요청 (봇 v2 재배선 8/24~27 — 지금 착수하지 않음)

1. **`/수업등록` 잔여 초과 경고** — 「김예지 잔여 3판 — 10판 등록 시 7판 초과. 계속?」
   **차단하지 않는다.** 경고 후 진행 허용.
   - 선행조건: `v_panel_roster` — **이미 실행돼 있다**(2026-08-19 실측). 이 선행조건은 해소됐다.
2. **초과 확정 시 오너 DM → [미수] / [부담] 버튼.** [부담] 선택 시 §3 정본 방식으로 등록 행 생성.
3. **패널 미수 목록에서 부담분 제외** — `paid_amount > 0` 필터로 처리된다(추가 컬럼 불요).
