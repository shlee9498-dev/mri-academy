# 문구·구현 정합 조사 (2026-08-13)

> **성격**: 조사 문서다. 이 문서만으로는 아무것도 바뀌지 않는다. 수정은 오너 승인 후 각 트랙이 한다.
> **범위**: ① 개인정보 동의 문구가 실제 전송·보관 구조와 일치하는지 ② 미구현 기능을 확정처럼 말하는 문구.
> **한계**: 이 문서는 **코드와 문구가 일치하는지만** 판정한다. 법적 적법성·필요성 판단은 하지 않으며,
> 그 판단이 필요한 항목은 "법률 판단 필요"로 표시하고 넘긴다. 교체안도 법적 방어가 아니라
> **구현과 일치하는 중립 서술**을 목표로 한다.

## Part 1. 개인정보 동의 문구 정합

### 1-A. "사이트에 저장·공개되지 않습니다" — **부정확**

**위치**: `apply.html:203` · `trainer-apply.html:139` (동일 문장 2곳)

> 입력 정보는 운영진에게만 전달되며 **사이트에 저장·공개되지 않습니다**.

| 구절 | 판정 | 근거 |
|---|---|---|
| "운영진에게만 전달" | ✅ 정확 | 디스코드 운영진 채널 + 오너 시트 |
| "공개되지 않습니다" | ✅ 정확 | 어떤 공개 페이지에도 렌더되지 않음 |
| "사이트에 저장되지 않습니다" | ⚠️ **오해 소지** | DB에는 안 들어가나 **디스코드·시트에 영구 보관**된다 |

"사이트에 저장되지 않는다"를 좁게 읽으면(= 웹사이트 DB) 사실이지만, 일반 이용자는 **"어디에도 남지 않는다"**로
읽는다. 실제로는 두 외부 시스템에 원본이 그대로 남고 파기 절차도 자동화돼 있지 않다.

**교체안** (구현과 일치하는 중립 서술):

```
개인정보(이름·연락처·디스코드 등)를 수강 상담 목적으로 수집·이용하는 데 동의합니다.
입력 정보는 운영진 전용 채널과 내부 관리 시트로 전달되어 상담·배정에 사용되며,
공개 페이지에는 표시되지 않습니다.
```

- "저장되지 않는다"는 삭제 — 사실이 아니다
- "사이트에 공개되지 않는다"는 유지 — 사실이다
- 보관처를 특정 상호 없이(디스코드/구글) **기능으로만** 서술 → 위탁사 변경 시 문구를 안 고쳐도 된다

> **법률 판단 필요**: 보관 기간·파기 절차를 동의 문구에 어디까지 써야 하는지는 이 문서 범위 밖이다.

### 1-B. 전적 수집 동의(`statsConsent`)가 **어디에도 기록되지 않는다** — 구조적 구멍

`apply.html:333`이 `statsConsent: "동의"/"미동의"`를 payload에 담아 보내는데,
**`server.js`가 이 필드를 한 번도 읽지 않는다**(전수 검색 결과 서버·패널 어디에도 참조 0건).
디스코드 임베드 필드에도 없다.

즉 **필수 동의로 받아놓고 동의 사실이 남지 않는다.** 나중에 "동의한 적 없다"는 말이 나오면 입증 수단이 없다.
클라이언트 체크박스는 프론트에서 우회 가능하므로 증거가 되지 못한다.

**이건 문구 문제가 아니라 구현 누락이다.** 최소 변경안 두 가지:

1. **디스코드 임베드에 1줄 추가** (가장 싸다 — 서버 1줄, 스키마 무관)
   ```js
   { name: "전적 동의", value: clip(b.statsConsent, 10) || "미기록", inline: true },
   ```
2. 시트 append 페이로드에도 같은 값 추가

> 서버는 이미 `required` 배열로 필수값을 강제하고 있으나 `statsConsent`는 그 배열에 **없다**.
> 프론트 체크만 있고 서버 검증이 없다 — 이것도 같은 뿌리다.

### 1-C. 성별 — **필수 수집인데 사용처가 없다**

| 항목 | 실측 |
|---|---|
| 클라이언트 | `apply.html:94-96` 라디오, **`required`** |
| 서버 | `server.js:3336` `required` 배열에 **`"gender"` 포함** → 없으면 400 |
| 실제 사용처 | **디스코드 임베드 표시 1곳뿐** (`server.js:3371` "성별/생년") |
| 상담·배정·정산·전적 로직 | **참조 0건** (전수 검색) |

배정·반 편성·전적 조회 어디에도 성별을 읽는 코드가 없다. **필수로 받을 코드상 근거가 없다.**

**최소 변경안** (선택 전환 — 수집은 유지하되 강제하지 않음):
1. `server.js:3336` `required` 배열에서 `"gender"` 제거
2. `apply.html:94`의 `required` 속성 제거
3. "비공개" 선택지는 이미 있으므로 그대로 두면 됨

**미수집 전환안** (더 강함): 위 2개 + 라디오 블록·payload·임베드 필드 삭제.
운영상 성별을 아예 안 봐도 되는지는 **오너 판단 영역**이다 — 코드는 안 쓰지만 사람이 참고할 수는 있다.

## Part 2. 과장 표현 스캔

### 2-A. 🔴 "트레이너 자동 배정" — **미구현**

**위치**: `index.html:803` · `809-810` · `817` · `777`

> 상담비 결제 → AI 챗봇 진단 → **트레이너 자동 배정**
> 트레이너 배정 — **24시간 내 자동**
> (프리미엄 카드 불릿) **즉시 배정**

**실측**: 자동 배정 코드가 **존재하지 않는다.**
- `/api/apply`는 디스코드 웹훅 + 시트 append가 전부다. 배정 로직 없음
- `/반배정`(`server.js:2078`)은 **운영진이 수동 실행하는 디스코드 역할 부여 명령**이지 신청서 기반 자동 배정이 아니다
- `students.trainer_id`는 사람이 채운다

**결정적 근거 — 챗봇 시스템 프롬프트가 스스로 부정한다** (`server.js:550`):

> `일정 확정, 결제 완료 확인, 환불 실행, 트레이너 배정 등 실제 처리는 직접 하지 말고 "상담에서 도와드린다"로 연결하세요.`

**퍼널 문구는 "자동 배정"이라 말하고, 챗봇 프롬프트는 "배정하지 말라"고 지시한다.** 정면 충돌이다.

**교체안**:

| 현재 | 교체안 |
|---|---|
| 상담비 결제 → AI 챗봇 진단 → 트레이너 자동 배정 | 상담 신청 → 실력 진단 → 맞는 트레이너 배정 |
| 트레이너 배정 — 24시간 내 자동 | 트레이너 배정 — 24시간 이내 안내 |
| 즉시 배정 | 빠른 배정 |

"24시간 이내 안내"는 `index.html:830`·`apply.html:253`이 이미 쓰는 표현이라 **사이트 안에서 일관된다**.

### 2-B. 🟡 "AI 챗봇 진단 — 성향·티어·목표 분석" — 부분 구현

**실측**: `/api/chat`은 실재한다 — Anthropic `claude-haiku-4-5` 프록시(`server.js`).
**"AI 챗봇"까지는 사실이다.**

문제는 **"진단"과 "분석"**이다. 이 챗봇은 상담 안내용이고, 티어·성향을 구조화해 산출하거나
그 결과를 배정에 넘기는 경로가 없다. 퍼널의 2단계로 그려져 있어 **파이프라인의 일부처럼 읽힌다.**

또한 `index.html:1214`에 이미 **"AI 답변이며 부정확할 수 있습니다"** 라는 고지가 붙어 있다 —
같은 페이지가 한쪽에선 "진단", 다른 쪽에선 "부정확할 수 있음"이라 말한다.

**교체안**: `AI 챗봇 진단 — 성향·티어·목표 분석` → `AI 챗봇 상담 — 궁금한 점 먼저 확인`

> 참고: BPI 자동진단(`diagnoseBpi`)은 **실재하는 진단 기능**이다. 다만 이건 챗봇이 아니라
> **신청서 제출 시 운영진 임베드에만 표시**되고 신청자에게는 안 보인다. "진단"을 살리고 싶으면
> 챗봇이 아니라 이쪽을 노출하는 게 구현과 맞다 — **별도 기능 제안이므로 이번 범위 밖.**

### 2-C. 🟡 "실시간 트레이너 현황 / 디스코드와 실시간 연동" — 과장

**위치**: `index.html:982-984`

**실측**:
- **서버**는 5분마다 디스코드 카운트를 갱신한다 (`server.js:995` `setInterval(refresh, 5*60*1000)`) → **"5분마다 갱신"은 정확**
- **프론트는 폴링하지 않는다.** `index.html:1144`의 IIFE가 **페이지 로드 시 1회만** `/api/stats`를 호출한다. `setInterval` 없음
- 따라서 화면 숫자는 **접속 시점에 고정**된다. 탭을 열어두면 갱신되지 않는다

"실시간 연동"은 웹소켓·스트리밍을 연상시키지만 실제는 **주기 갱신 캐시의 스냅샷**이다.
문구가 자기 옆에서 "5분마다 갱신"이라 말하고 있어 이미 모순을 노출한다.

**교체안**: `실시간 연동 · 5분마다 갱신` → `5분마다 갱신` (또는 `최근 업데이트 N분 전`)

기존 코드가 이미 `실시간 연동 · N분 전 업데이트`를 렌더하므로, **"실시간 연동 · " 접두어만 빼면**
나머지는 그대로 정확해진다. 최소 변경이다.

> `index.html:682`·`849-850`의 "실시간"(화면 공유로 실시간 관전·피드백)은 **수업 방식 서술이고 사실이다.**
> 스캔에 걸렸지만 **수정 대상 아님.**
